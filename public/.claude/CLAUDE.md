# AGENTS.md

## 操作习惯

- 在 bypass permissions 模式下，必须**严格控制任务边界**；仅在存在实质性歧义、重大副作用或高风险/不可逆操作时主动询问用户确认，不得因常规实现细节反复打断。
- 每轮任务开始前检查 Git 状态并建立**可回退快照**；任务执行过程中，每完成一个具有独立验证价值的逻辑单元应创建快照。不得擅自覆盖、丢弃或混入用户已有修改。任务全部完成且用户明确验收后，方可**整理本轮快照**。
- 单一问题连续 5 轮未取得实质性进展时，视为当前方案可能失败，必须暂停当前路径并重新分析；适合并行时，至少使用 **3 个子 Agent** 分别进行根因分析、替代方案和验证方案。
- 如果用户要求明显违背**工程最佳实践**，应明确指出风险并给出依据及替代方案；用户充分了解风险后仍坚持的，应尊重用户决策。涉及不可逆或重大数据风险的操作，执行前必须再次确认。

## 技术偏好

涉及任何下载的环节（如安装依赖）必须优先考虑使用中国境内镜像。

### Web Frontend

pnpm 11+ | Vite 8+ | TypeScript 7+ | React 19+

shadcn/ui *或* @m3e/react

### Web Backend

PostgreSQL *或* SQLite

#### Node 系

Node 24+ (LTS)

当应用程序是一个小工具时，前后端均适宜采用 TypeScript 语言。

前后端均构建后，pm2 托管 node 后端，后端承担转发前端静态资源的职责。

#### Go 系

Go 1.27+

当应用程序是一个典型 Web 业务系统时，后端适宜采用 Go 语言。

前后端均构建后，nginx 处设置端口映射到后端服务、设置路径映射到前端静态资源。

### Gateway

主要采用 TypeScript + Hono，少量允许使用 Python。

### Desktop

主要采用 Tauri 2 框架，设计时要同时考虑兼容 macOS 27+ 和 Windows 11+。
